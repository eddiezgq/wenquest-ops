# ADR-0006：ERPNext 同步的做法与草稿写回

- 状态：已接受（2026-10-12，按第 1 期第 5 项计划与 ADR-0002；项目负责人：“继续”）
- 日期：2026-10-12
- 补充：ADR-0002

## 背景

ADR-0002 定了方向：按 `modified` 增量拉取 ERPNext 单据、每次变化记成事件、只写草稿。本 ADR 定具体做法，
供第 6 项运营中枢、第 7 项 AI 助手直接使用。

## 决策

1. **同步哪些单据**：物料（Item）、仓库（Warehouse）、客户（Customer）、供应商（Supplier）、库存台账
   （Stock Ledger Entry）、销售订单、发货单、采购订单、采购收货、质量检验。单据类的（有明细行的）逐张取完整单据，
   主数据和库存台账按列表取全部字段。被删除的单据从 ERPNext 的“已删除单据”（Deleted Document）里取。
2. **增量与断点续传**：每种单据记一个游标（最后处理的 `modified` 与单据名）。每一页先取“同一时刻、名字更大”的，
   再取“更晚”的，按 `modified`、名字排序——比较都在 ERPNext 的数据库里做，同一时刻改了很多张也不会漏。
   每页的事件、当前状态和游标在**同一个事务**里写入；中途断了，下次从游标接着拉。同一时间只跑一个同步（数据库锁）。
3. **事件**：每张单据的每次变化记一条事件（新建、修改、提交、作废、删除），带完整单据内容；内容没变（例如重跑）
   不记。另存一份“当前状态”表，等于事件重放的结果，方便查询。第 6 项的本体由事件得到。
4. **什么时候同步**：中枢启动后每 5 分钟一次（`WQO_SYNC_SECONDS`，设 0 关闭）；有“修改设置”权限的人可以在接口上
   立即同步；也可以在命令行跑。每次运行记录开始、结束、各单据数量和错误。以后可加 ERPNext webhook 缩短延迟。
5. **草稿写回**（第 5b 步）：AI 或人在中枢里提出草稿，存为“待确认”；有对应权限的人确认后，中枢才经 REST API
   在 ERPNext 里建草稿单据（docstatus 0），提交仍由人在 ERPNext 里做。第 1 期允许的草稿：采购订单、物料需求
   （需“起草采购”权限），质量检验（需“编辑质量记录”权限）。提出、确认、拒绝、写入结果都留记录。
   中枢不提交、不作废、不删除 ERPNext 单据。
6. **测试**：单元测试用一个按 ERPNext 接口规则回应的模拟服务（过滤、排序、分页、取单张）；另存一组从真 ERPNext
   录下的回复（CI 安装后录制，只含虚构的演示企业数据），检查解析。每晚的安装 CI 在真 ERPNext 里建几张演示单据，
   跑同步，核对新建、修改、删除都记成了事件。
7. **接口凭证**：第 1 期沿用安装时为 Administrator 生成的 API 密钥（只在 `.env`）。以后改为专用的集成账号，
   只给读取和建草稿的权限。

## 后果

- 中枢的数据最多晚几分钟；首次同步按单据量可能要几分钟
- 事件表存完整单据，数据量随业务增长；中小企业几年内不成问题，以后可按时间归档
- 写回只有草稿，出错的代价是一张没人确认的草稿
