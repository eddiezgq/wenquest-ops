# ADR-0001：产品范围、架构与许可边界

- 状态：已接受（2026-10-12，项目负责人：“同意”“开始第一期”“仓储”“按建议”，产品名 WenQuest Ops）
- 日期：2026-10-12

## 背景

项目负责人决定只做美国和国际市场、慢慢来。美国中小企业普遍缺一个把各个系统连起来的集成层：订单、库存在一处，
质量记录在纸上或 Excel，出了问题说不清前因后果；不少公司招了 AI 岗，老板和本人都不清楚该做什么。
已有的“问渠数字工厂”（`eddiezgq/freecad-ai-parts` 的 `factory/`）做过这一层，但面向中文教学和制造场景。

## 决策

1. **产品**：WenQuest Ops，分模块的集成平台，面向所有行业的中小企业（10–200 人）。
2. **架构**（自下而上）：
   - 底座：ERPNext 官方镜像（订单、库存、采购、财务），不改其源码；
   - 运营中枢：我们的服务（FastAPI + PostgreSQL），从 ERPNext 同步数据，建成对象关系网（本体），算指标、追因；
   - 业务模块：质量、仓储分销、生产、设计到生产、行业模板，按需开启；
   - AI 助手：在中枢之上问答、起草、提醒，只起草、由人确认；
   - 网页：Vue 工作台；
   - 托管接口（收费）：运费面单、电商订单、QuickBooks、销售税、EDI，作为我们托管的云服务被调用；
   - 课程与帮助。
3. **许可边界**：ERPNext 是 GPLv3。我们只通过 REST API 与它通信、用官方镜像运行，不修改、不链接它的代码，
   我们的服务是独立程序。本仓库私有，版权归项目负责人；底座以后是否开源另行决定。收费部分只以托管服务提供。
   （以上为工程上的理解，正式商用前请律师确认。）
4. **分期**：第 0 期访谈与第 1 期并行；第 1 期做英文底座与四个核心模块（底座、运营中枢、AI 助手、质量）；
   第 2 期仓储分销模块与第一个接口；第 3 期课程。每期过门槛才进下一期（`docs/plan.md`）。

## 后果

- 中枢以 ERPNext 为唯一业务数据来源，不再依赖数字工厂的仿真车间、消息总线、PLC
- 换底座（如 Odoo）只需换同步层，中枢与模块不动
- 数字工厂里与教学、CAD、仿真分析相关的部分不进第 1 期
