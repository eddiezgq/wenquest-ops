# ADR-0027：演示企业体验账号——官网申请即开、每晚还原

- 状态：已接受（2026-11-07，项目负责人问“不记录数据，体验什么意思”，听了解释后选“两种都给”：共用演示账号随便看、每晚清空；要录自己数据的，在管理页一键转成试点企业）。方向见问渠主仓库《实施细则 · 第 96 轮》第八节。
- 关联：ADR-0025（试点企业，开通队列）、ADR-0005（账号）

## 背景

国内客户想自己先看看问渠质量 ERP，现在只能“预约演示”。正式试用走 ADR-0025 的试点企业（每家一套，0.85 GB 内存，名额 3 家），
不适合给每个随手申请的人开。第 96 轮定了：在**演示企业**（海港五金供应（演示））里给申请人开一个账号，多人共用，每晚还原。

## 决策

1. **开通走 ADR-0025 的同一个队列文件夹**（不新开网络接口、不加共享钥匙）：问渠网关在官网申请自动开通（第 96 轮）且勾了
   “问渠质量 ERP”时，写 `trial-<编号>.json`（姓名、邮箱、语言）；`pilot-runner.sh` 每分钟取走，在演示安装里执行
   `python -m wqops.hub.trial add`，结果（账号、初始密码、网址）写 `res-trial-<编号>.json`，网关发邮件后删除。
2. **体验账号**：`users.source = 'trial'`，角色**质量**（quality；ERPNext 里是质量经理一类权限），带到期日（默认 30 天，
   `WQO_TRIAL_DAYS`）；首次登录要改密码（`must_change`）；不能加人、不能改企业设置（质量角色本来就没有这些权限）。
   到期由夜间任务停用。同一邮箱再申请：未到期就重发一个新初始密码，已到期不再开（转人工）。每个体验账号 AI 每天 20 次
   （`WQO_TRIAL_AI_DAILY`），企业整体上限照旧。
3. **每晚还原**（演示安装，北京时间 03:30，持部署锁）：`deploy/demo-reset.sh`
   1. 导出体验账号（邮箱、姓名、密码哈希、到期日、是否已改密码）；
   2. 用“干净快照” `backups/demo-golden.tar.gz` 执行 `restore.sh --yes`；
   3. 跑一遍 `upgrade.sh` 的迁移部分（hub 数据库迁移、`bench migrate`、`erp_setup apply`），让旧快照跟上当前版本；
   4. 导回未到期的体验账号（密码不变）；
   5. 用还原后的干净状态**重拍快照**（这样快照永远是“干净 + 最新版本”）。
   失败就停在原样并写日志，第二天再试；不影响试点企业。
4. **首个干净快照**：上线当晚从演示企业的现状拍（`demo-reset.sh snapshot`）。在那之后对演示企业的任何改动（包括项目负责人
   自己演示时录的数据）**每晚都会被还原掉**。要改演示数据的基线：改好后手动跑一次 `demo-reset.sh snapshot`。
5. **只在演示安装上**：`WQO_DEMO_TRIAL=1` 才开（国内、美国演示服务器都可以开；先开国内）。试点企业不受影响。
6. 体验账号进 ERPNext 走现有的单点登录（第一次进 ERPNext 时按角色建用户），还原后同样会再建。
7. **两种体验并存**（项目负责人 11-07 定）：共用演示账号只用来“看看系统怎么用”，开通邮件和工作台顶上都写清楚
   “这是多人共用的演示企业，每晚清空，请不要录入真实数据；要录自己的数据，回复邮件申请独立试点”。要录自己数据的，
   项目负责人在问渠学习平台“体验单位”页对这家单位点“转成质量 ERP 试点”（即 ADR-0025 的邀请，名称、联系人、邮箱自动带上）。

## 后果

- 演示企业变成“公共沙盘”：任何人在里面做的事第二天就没了；申请人看到的是同一套演示数据，也能看到别的体验者当天的操作
  （演示数据是虚构的，不涉及真实企业数据）。
- 每晚有几分钟演示企业不可用（还原期间）。
- 多一个快照文件（约几百 MB），放在演示安装的 `backups/` 里，不计入每日备份的保留份数。
- 测试：`trial add / export / import / expire` 的单元测试（不联网）；`demo-reset.sh` 用 `tests/test_deploy.py` 的脚本检查方式覆盖步骤顺序和失败退出。
