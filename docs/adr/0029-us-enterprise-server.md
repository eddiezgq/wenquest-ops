# ADR-0029：美国的问渠质量 ERP 搬到企业服务器

- 状态：已接受（2026-11-10，项目负责人：“1a，2 每家一套，3 可以”；2026-11-11：“开始搬吧，服务器都租好了”）
- 日期：2026-11-11
- 关联：WenQuest 仓库《实施细则 · 第 146 轮：美国服务器教育与企业分开》

## 背景

美国原来只有一台服务器（8 GB），上面同时跑着学习平台、数字工厂和问渠质量 ERP，可用内存只剩约 1.3 GB，新试点企业开不出来。
项目负责人定：教育和企业业务分开，另租一台**企业服务器**（DigitalOcean 纽约，161.35.185.35，8 GB，Ubuntu 24.04）。

## 决策

1. **美国的部署目标改成企业服务器**。`deploy-us.yml` 仍然读 `US_DEPLOY_HOST`；切换当晚由项目负责人把这个 secret 改成新 IP。
   在那之前可以手动运行，填 `host` 先在新服务器上装好（不切 DNS）。
2. **前门（Caddy）不在本仓库**：企业服务器的 Caddy 由 WenQuest 仓库的 `deploy/enterprise` 部署，网络名照旧叫 `qms-edge`，
   安装仍然用 `--edge`。所以本仓库的安装、升级、试点开通脚本都不用改。
3. **试点开通的交接文件夹**照旧是 `/opt/wenquest/pilot-queue`，`pilot-runner.sh` 不变。WenQuest 网关现在在另一台机器上，
   两边之间由 WenQuest 的交接桥（`bridge-sync.py`，每分钟一次，HTTPS 加钥匙）搬文件。
4. **部署钥匙不变**：原服务器上 deploy 用户认的公钥（含本仓库 `US_DEPLOY_SSH_KEY` 的那把）已经加到企业服务器上。
5. 原服务器上的质量 ERP，在切换核对无误后停掉，记录保留，作为回退。

## 后果

- 每家试点企业一整套（ADR-0025 不变）；8 GB 约能放 5 家，满了再加服务器或升配。
- 切换当晚，`qms`、`qms-erp`、`*.qms`、`*.qms-erp` 四条 DNS 改指新服务器；回退就是改回原 IP，同时关掉交接桥。
