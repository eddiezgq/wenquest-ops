# ADR-0007：运营中枢——本体、指标、异常与追因、工作台

- 状态：已接受（2026-10-12，按第 1 期第 6 项计划与 ADR-0002；项目负责人：“继续”）
- 日期：2026-10-12
- 补充：ADR-0001、ADR-0002、ADR-0006

## 背景

第 5 项把 ERPNext 的变化记成了事件（`erp_events`）。第 6 项把它们组织成企业的业务全貌：有哪些对象、彼此什么关系、
关键指标如何、哪里出了问题、问题从哪来。做法沿用数字工厂第 17 轮“厂情中枢”（本体 → 指标 → 异常 → 追因），
但数据只来自 ERPNext 与企业清单，界面全英文，去掉仿真、推演、车间相关部分。

## 决策

1. **本体**（`wqops/ontology/*.yaml`，英文）：8 个领域——客户、销售与交付、产品与物料、供应、仓储、质量、人员、
   财务——加中枢自己的“异常”。每个对象类型写明来源（ERPNext 单据或企业清单）、键、属性（带单位）、链接（含反向叫法）、
   成熟度：`have` 已同步；`erp` ERPNext 里有、还没同步（如销售发票、付款，诚实标出）。启动时校验定义。
2. **对象由事件得到**：投影器按事件编号顺序读 `erp_events`，每种单据一个映射函数，写 `ont_objects`、`ont_links`；
   记住处理到的事件编号，增量更新；可清空后从头重放，结果相同。每次同步后自动投影。人员与部门来自企业清单。
   库存现存量、库存金额由库存台账（Stock Ledger Entry）累加得到，不另存估计值。
3. **指标**（默认最近 30 天，可选 7/30/90 天；口径写在代码和帮助里，缺数据时显示 unknown，不显示 0）：
   - 按时交付率：期内**发货完成**的销售订单中，最后一张发货单日期 ≤ 订单交期的比例；
   - 缺货：在手量（所有仓库，不含质检隔离仓）小于未发货的销售需求的物料数，列出短多少；
   - 库存金额：库存台账的金额变化累计（不含已作废台账），按仓库分开；
   - 库存天数：库存金额 ÷（最近 90 天发货出库的金额 ÷ 90）；90 天内没有出库则 unknown；
   - 供应商按时率：期内采购收货的每一行，收货日期 ≤ 对应采购订单行的计划到货日即为按时，按供应商汇总；
   - 未关闭不合格：期内检验结论为不合格（Rejected）的质量检验，第 8 项的不合格品单（NCR）关闭后才算关闭。
4. **看板**：上述指标、趋势（按周）、需要关注的对象，按角色只显示有权限看的部分（ADR-0005 的查看权限）。
5. **异常**：规则检测，每次投影后跑一轮。第 1 期规则：订单逾期未发、订单有缺货风险（交期 7 天内且缺货）、
   缺货、采购逾期到货、供应商按时率低于 90%（期内至少 3 行）、检验不合格。生命周期：新发现 → 已确认 → 处理中 →
   已解决（条件消失自动解除）/ 人工关闭；同一规则、同一对象只开一个；状态变化留记录。阈值写在规则目录里，可调。
6. **追因**：从异常或任意对象出发，沿本体链接往上游找原因、往下游算影响，每一步写明依据（哪张单据、哪条规则、
   哪个数）。第 1 期链路：订单延误 → 缺货的物料 → 这些物料未到的采购单 → 供应商（及其按时率）；
   检验不合格 → 收货单 → 供应商、物料 → 用到这批物料的未发订单 → 客户。最多 6 跳、200 个节点。
7. **工作台**（ADR-0001 定的 Vue）：`web/` 用 Vite + Vue 3 构建，镜像构建时编译，中枢直接提供静态文件；
   页面：看板、对象浏览（搜索、对象页、关系、时间线）、异常列表与追因图。英文界面。
8. **分四步交付**：6a 本体、投影、对象接口；6b 指标与看板接口；6c 异常与追因；6d 网页工作台。
   每步的测试用虚构的演示数据，指标与手算核对、追因链逐步核对；第 9 项再做 90 天的完整演示企业。
9. **复用**：从数字工厂复制并改写 `hub/ont/schema.py`（定义校验）、`store.py`（存储思路）、`anomaly.py`（生命周期）、
   `chain.py`（走图与依据），文件开头注明出处；不复制推演、动作、车间、教学相关代码。

## 后果

- 指标口径公开、可手算核对；企业对口径有不同理解时改规则目录或代码，不改数据
- 网页需要 Node 构建，只在镜像构建和 CI 里跑，企业服务器不需要装 Node
- 本体随模块增加：第 8 项质量加不合格品、8D、纠正预防；第 2 期仓储加更多对象
