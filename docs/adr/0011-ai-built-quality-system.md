# ADR-0011：AI 搭建质量体系——把标准软件化、流程化、运行化

- 状态：已接受（2026-10-13，项目负责人：“要有ai建质量模块的功能……根据企业的情况，自动配置”“我是让你把标准软件化，
  流程化，管理和运行化，不是抄”“好”）
- 日期：2026-10-13
- 补充：ADR-0009、ADR-0010

## 背景

企业本来就有程序文件、表单和历史记录，但多数是散在文件夹和 Excel 里，跟实际做法对不上。项目负责人要的不是一套
模板文件，而是让 ISO 9001、ISO 13485 这类标准在系统里真的跑起来：每条要求变成可以执行的过程、控制点和检查，
企业的资料和做法由 AI 归类、套进来，体系的运行状况由系统根据记录持续检查。

## 决策

1. **标准 = 可运行的过程包**（不是文本）：每个标准是一套“过程、步骤、必填记录、签字、控制点、检查规则、指标”，
   每个控制点标明对应条款号，方便内审外审对照。标准原文不进系统，要求摘要由我们自己写；条款对照由项目负责人审核。
2. **流程配置化**：质量流程（状态、步骤、必填项、签字人规则、职责分离、自定义字段、编号规则、处置类型、抽样方案
   引用等）写成有版本的配置；代码按配置执行，并校验配置本身。第 1 期的 NCR、CAPA 流程成为默认配置。
   红线不可配置掉：判定由确定性代码执行、签字重输口令、留痕只增不改、职责分离只能加严（ADR-0010）。
3. **程序文件由流程生成**：系统里的流程就是程序；程序文件按当前配置自动生成，配置改了出新版本。
4. **运行化**：检查规则根据实际记录持续评估每个控制点（例：CAPA 都做了有效性验证；培训、校准在有效期内；
   管理评审按周期召开；供应商已批准且未过复评期），汇成“体系运行状况”，红灯可点进看是哪些记录；
   内审清单与证据从记录直接生成。
5. **资料库与 AI 归类**：企业成批上传文件（以后接 SharePoint、Google Drive），AI 识别类型（程序、作业指导书、表单、
   记录、规格、证书、外来文件）、所属过程、编号、版本、日期、负责人；人确认后进入受控管理（版本、指纹、作废写原因，
   沿用 dee-qms 文件控制）。结构化的历史记录（台账）经人确认的字段对照后由代码导入对应模块，标明来源。
6. **AI 自动配置**：按企业清单（行业、规模）、问卷与要认证的标准选过程包；AI 读企业自己的程序，把过程包调成企业的
   样子（编号、审批人、处置类型、表单字段、抽样方案），每条改动注明出自哪份文件哪一段，人逐条确认，另一人启用，
   启用后冻结存指纹。差距报告列出每个控制点有没有证据、在哪；缺的列成待办，AI 可起草，人审批。
   企业可选只用规则抽取、不把资料送大模型。
7. **排期**：第 1 期先完成第 9、10 项。第 2 期：① 流程配置化 + 资料库与 AI 归类；② ISO 9001 过程包与自动配置、
   体系运行状况；③ ISO 13485 过程包，同时移植 dee-qms 的受监管模块（文件控制、培训、校准、投诉、内审、变更、
   风险、生产记录、追溯召回、管理评审）。每步先写 ADR。
8. **不承诺认证**：系统帮企业建体系、运行和备审，认证由认证机构决定。

## 后果

- 质量模块从“固定流程”变成“按标准与企业情况配置的流程”，前面的工作成为默认配置，不浪费
- 条款对照与要求摘要需要质量专业人员审核，项目负责人把关
- 资料与记录会经过企业自己的模型密钥处理；可关闭
