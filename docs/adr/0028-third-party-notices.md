# ADR-0028：第三方开源组件的许可说明

- 状态：已接受（2026-11-08，项目负责人：“按方案做”）
- 日期：2026-11-08

## 背景

ADR-0001 定了许可边界：ERPNext（GPLv3）只用官方镜像、只通过 REST API 通信，不修改、不链接，我们的服务是独立程序。
这条线一直守着。但有一处还没做到位：国内服务器连不上 Docker Hub，`images.yml` 把 ERPNext、MariaDB、Redis、PostgreSQL、
Caddy 的官方镜像原样转存到国内镜像仓库，再由国内安装使用。这是**转发**开源软件（没有修改），GPL 等协议要求随附许可证、
告诉对方源码在哪里。现在仓库里、安装输出里、产品界面里都没有这份说明。私有部署（同一套代码装在企业自己的机器上，第 109 轮 D-5）
以后，我们的中枢镜像也交到企业手里，里面带着若干开源库，也应当列明。

## 决策（草案）

1. 仓库根目录加 `THIRD_PARTY_NOTICES.md`（中英文）：逐个列出用到的开源组件、版本、许可证、官方源码地址：
   - 镜像：ERPNext v16.34.1（GPLv3）与 Frappe 框架（MIT）、MariaDB 11.8（GPLv2）、Redis 6.2（BSD-3-Clause）、
     PostgreSQL 16（PostgreSQL License）、Caddy 2.10（Apache-2.0）；
   - 中枢镜像里的 Python 库（FastAPI、Uvicorn、httpx、psycopg 等，许可证按各自声明）与网页用到的 npm 库，由脚本 `tools/third_party.py` 生成，
     测试检查清单是否和依赖一致、文件是否最新（加了依赖忘了登记会报错）。
2. 说明写明：这些镜像是**未经修改**的官方版本，源码见各自官方地址；ERPNext 的源码 `https://github.com/frappe/erpnext`
   对应标签 `v16.34.1`。按 GPLv3 第 6 条，我们在三年内应要求提供对应源码（实际做法：给出官方源码地址和标签）。
3. 三处能看到：仓库根目录（也打进中枢镜像）；`install.sh` 装完后打印一行，指向产品里的“帮助 → 关于与开源组件”页
   （`/help/about`），那一页列出组件和许可证。
4. 国内镜像仓库转存时，镜像内容不动（镜像里本来带着各自的许可证文件），不另改名。
5. 不改变 ADR-0001 的任何边界；我们自己的代码仍然私有，版权归项目负责人。私有部署给企业的许可条款（例如“仅限本企业使用、
   不得转售”）另行决定，不在本 ADR 里。
6. 以上为工程上的理解，正式商用前请律师确认（同 ADR-0001）。

## 后果

- 多一个文件和一个检查；加依赖时要能通过清单检查（脚本自动生成，一般不用手改）。
- 帮助页多一个“关于”入口。
