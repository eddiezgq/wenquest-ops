# ADR-0008：AI 助手——问答、每日简报、起草，人确认后才写回

- 状态：已接受（2026-10-12，按第 1 期第 7 项计划与 ADR-0003；项目负责人：“继续”）
- 日期：2026-10-12
- 补充：ADR-0003、ADR-0006、ADR-0007

## 背景

第 6 项有了对象、指标、异常、追因。第 7 项让 AI 在这些之上工作：用英文回答问题、每天出简报、起草单据和消息。
原则不变：AI 只起草，人确认后才写进 ERPNext 或对外发送；每次运行留记录。做法参考数字工厂 17D（工具、引用、
数字核对、运行记录、规则版兜底），去掉教学和推演相关部分。

## 决策

1. **模型**：默认 Claude（Anthropic Messages API，工具调用），密钥 `WQO_ANTHROPIC_API_KEY`（或 `ANTHROPIC_API_KEY`），
   模型 `WQO_AI_MODEL` 可改。经 httpx 直接调用，不加 SDK 依赖；接口留一层，以后可换其他提供方。
   没配密钥时用**规则版**：识别常见问题（逾期订单、缺货、指标、异常、某个对象怎么了），按固定步骤调同一套工具，
   答案同样带依据。简报和起草不依赖模型。
2. **只用中枢的工具取数**（按提问人的权限过滤，与网页看到的一样）：搜索对象、读对象、查原因与影响、取指标、
   列异常、读异常。模型看不到数据库，也不能联网。
3. **起草工具**：补货采购单、不合格报告（NCR）、给客户的延误说明。都只生成“待确认”草稿（ADR-0006 第 5 条的草稿表）：
   - 补货采购单：按缺货量、该物料最近一张采购单的供应商和单价、企业清单里的主仓库算出；缺供应商就不起草，
     说明缺什么。确认后在 ERPNext 建采购订单草稿；
   - 给客户的延误说明：按订单、交期、追因结果写成邮件正文；确认后标为“可发送”，由人复制发出（第 1 期不接邮件）；
   - 不合格报告：按不合格的质量检验、收货单、供应商写成 NCR 草稿；确认后成为中枢里的 NCR 记录，第 8 项质量模块
     接着做处置、8D 和纠正预防。
   草稿分两类目标：`erpnext`（写 ERPNext 草稿单据）与 `hub`（只在中枢里，消息与 NCR）。确认权限：采购单要
   “起草采购”，消息要“查看销售”，NCR 要“编辑质量记录”。
4. **引用与数字核对**：工具结果里的对象写成 `[Type:Key]`，网页显示为链接；回答里的每个数字都要在本次工具结果或
   问题里出现过，出现不了的那句标为“unverified”，运行记录里记下核对结果。
5. **运行记录**：每次问答、简报、起草存一条：谁、问了什么、用的引擎和模型、每次工具调用（参数与结果摘要）、
   回答、核对结果、生成的草稿、用量、错误、反馈（有用 / 没用）。草稿记着来自哪次运行。
6. **每日简报**：每天 7:30（企业时区）按昨天和今天的数据生成：指标、新出现与仍未处理的异常、待确认的草稿、
   今天到期的订单与采购单。数字全部由代码算，模型（有密钥时）只改写文字，数字核对不过就用规则版文字。
   也可以随时点“生成”。
7. **网页**：助手页（提问、看用了哪些工具和依据、生成的草稿）；草稿页（待确认 / 已确认 / 已拒绝，确认、拒绝）；
   看板显示今天的简报。
8. **测试**：不调用真实模型。用模拟的 Messages API 按脚本回复（工具调用、最终回答），核对工具按权限过滤、
   起草不经确认不写回、数字核对、运行记录；规则版有固定的问答题目。
9. **分三步交付**：7a 模型接口、工具、问答、运行记录、规则版；7b 三种起草与草稿页；7c 每日简报与助手页。

## 后果

- 没有模型密钥也能用简报、起草和常见问答；有密钥时问答更灵活
- 模型费用由企业自己的密钥承担；运行记录里有用量，便于估算
- 以后接邮件、Teams、Slack 时，“可发送”的消息再加发送动作，仍要人确认
