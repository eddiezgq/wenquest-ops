# ADR-0026：PLM 模块（零件库与编码、BOM 版本、型号衍生配置、设计变更）——先给缝纫机企业

- 状态：已接受（2026-11-06，项目负责人：“好的，开始”；方案见问渠主仓库《实施细则 · 第 109 轮》）
- 日期：2026-11-06
- 补充：ADR-0001（架构与许可边界）、ADR-0010（质量原则）、ADR-0017（17g 变更控制）、ADR-0020（导入与机器接口）、
  ADR-0023（中文版）、ADR-0025（试点 SaaS）

## 背景

项目负责人想给缝纫机企业（台州、宁波一带的中小企业）做一套 PLM：一台工业缝纫机上千个零件，平缝、包缝等
各有大量衍生型号，BOM 乱、改了零件说不清影响到哪些型号。大 PLM 买不起，通用 PLM 不懂缝纫机。
我们已有 ERPNext 底座和质量模块（变更控制、CAPA、追溯），问渠主仓库里有缝纫机设计软件（网页版 + FreeCAD 工作台、
本单位零件库）。PLM 做成本平台的一个模块，不另做系统；先服务缝纫机企业，做法对其他离散制造企业通用。

## 决策（项目负责人 2026-11-06 已选）

1. **模块**：`plm`，在企业清单 `modules` 里打开才出现；没开的企业看不到 PLM 的页面和接口。
2. **第一版四块**：26a 零件库与编码；26b BOM 版本；26c 型号衍生配置；26d 设计变更（ECN，用 17g 变更控制）。
   配件手册与爆炸图放第二版。
3. **零件主数据就是 ERPNext 的物料（Item）**：PLM 在中枢里只加 ERPNext 没有的东西——版本（A、B、C…，跳过 I、O、Q）、
   状态（设计中 → 已发布 → 停用）、类别参数、模型和图纸附件。新建零件时由人在页面上确认，中枢用 REST API 建 ERPNext 物料。
4. **两层 BOM**：设计 BOM 在 PLM 里，有版本、能比较两版；发布时人签字，中枢在 ERPNext 建对应的 BOM。
   按 ADR-0001 与草稿规则（中枢从不提交、取消、删除 ERPNext 单据），ERPNext 里的 BOM 建成**草稿**，
   由人在 ERPNext 里提交；PLM 页面显示它在 ERPNext 里是草稿还是已提交（读不到时为“未知”）。生产只认发布版。
5. **发布前检查**（代码判定，缺数据为“未知”、不算通过）：零件——类别必填参数齐全、在 ERPNext 里有物料；
   BOM——至少一行、子件都已发布、没有循环、数量大于 0、有单位、外购件在合格供应商名录里有批准的供应商。
6. **已发布的不能改**：零件、BOM 发布后内容锁定（数据库层拦改删）；要改就出新版本，新版本必须挂一张已批准的
   “产品”类变更（17g）。26d 再在变更上加“改了哪些零件和 BOM、生效方式、影响分析”。
7. **编码**：企业按类别定前缀和位数（默认取类别表），系统发号、不重号；也可以填老编码（不能和已有物料重复）。
8. **查重**：新建零件时，在同类别里找必填数值参数都相同（相差 1% 以内）的已有零件，提示复用；有相似的要人勾选
   “确实是新零件”才建。AI 查重（名称、描述相似）以后在此规则之上加。
9. **类别表**：沿用问渠缝纫机设计软件“本单位零件库”的类别和字段（电机、机针、旋梭、送布牙……），加通用的
   轴、连杆、凸轮、机壳、紧固件、轴承、电子件、其他；每个类别有必填参数、单位、范围。企业以后可加自己的类别（另开 issue）。
10. **权限**：新增 `plm:view`、`plm:edit`（建零件、改设计中的内容）、`plm:release`（签字发布）；新增角色
    `engineering`（工程 / 设计）。老板全有；质量、运营经理能看。
11. **附件**：每个零件版本可挂 STEP、图纸（PDF、DXF、DWG）、图片，存文件卷、记 SHA-256；发布后不能增删。
12. 中英文同一套代码；国内 AI 只用 DeepSeek（本期 26a、26b 不调用 AI）。

## 分步

- **26a 零件库与编码**：类别表、编码规则、零件与版本、查重、建 ERPNext 物料、附件、发布签字、反查（用在哪些 BOM）。
- **26b BOM 版本**：设计 BOM 编辑、比较两版、发布检查与签字、建 ERPNext BOM 草稿并显示状态、新版本挂变更。
- 26c 型号衍生配置、26d ECN（挂零件 / BOM、生效方式、影响分析、CAPA 发起）、26e 接设计数据（FreeCAD 推送、STEP 与 Excel 导入）、
  26f 缝纫机演示企业：各自开 PR，按问渠主仓库第 109 轮细则的顺序做。
- 26e 补充：写入在中枢里要么全成要么全不成，ERPNext 物料在提交后再建（建不成可重试）；类别、自制 / 外购按文件或名称末尾的词
  猜（只是建议，人改）；旧 BOM 的单位在 ERPNext 没有时先建 UOM（和物料组“PLM”一样，属主数据，不是单据）。
  演示数据 `demo/plm/`：虚构平缝机 347 个零件、29 个部件。

## 后果

- 中枢多了一组只增不改的 PLM 表；ERPNext 仍是物料与生产 BOM 的唯一来源。
- 发布 BOM 后多一步“在 ERPNext 里提交”，换来“中枢从不提交 ERPNext 单据”的边界不变。
- 版本修改依赖 17g 变更控制，没开质量模块的企业也要能用变更控制（变更控制在 `quality:*` 权限下，工程角色可看）。
