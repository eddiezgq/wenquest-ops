# ADR-0012：演示企业 90 天数据、英文帮助与引导、自动录制的截图和视频

- 状态：已接受（2026-10-13，按第 1 期第 9 项计划；项目负责人：“好”）
- 日期：2026-10-13
- 补充：ADR-0006、ADR-0007、ADR-0009、ADR-0010

## 背景

第 1 期要让试点企业和课程学员在一套有内容的系统上看到每个模块怎么用。演示企业 Harbor Lane Supply (Demo) 已在
企业清单里，但 ERPNext 里还没有业务数据。

## 决策

1. **数据生成与写入分开**：`wqops/demo/scenario.py` 是确定性的模拟（固定随机种子），从“今天往前 90 天”逐日推演：
   期初库存、按再订货点下采购单、到货（供应商各有提前期，其中一家常晚到）、来料检验（含一批不合格、一个参数逐步漂移）、
   销售订单与发货（有货才发，一种关键物料断货导致订单逾期），输出按日期排序的单据清单。
   `wqops/demo/load.py` 把清单经 REST API 写进 ERPNext 并提交，再在中枢补一组质量记录（不合格品、纠正预防，含一项逾期措施）。
2. **只写演示企业**：企业清单不是 `demo: true` 时拒绝运行；写入的客户、供应商、物料名称全是虚构的，客户与供应商名带
   “(Demo)”字样。这是安装工具（由 IT 运行），不是 AI 写回；AI 写回仍只建草稿（ADR-0006）。
   ERPNext 只接受“收货前要检验”物料的来料检验，默认还会拒收有不合格检验的收货单；演示站把该设置改为“警告”，
   以便不合格批照常收货再移到质检隔离仓（只在演示站改）。
3. **数量控制**：约 25 种物料、10 个客户、4 个供应商、90 天约 100 张销售订单，写入在几分钟内完成，可在 CI 安装任务里跑。
4. **典型问题**（第 6–8 项的指标、异常与追因能看到）：供应商按时率偏低；断货导致订单逾期与交期临近的订单缺货；
   逾期未到的采购单；来料不合格（演示数据里已开好不合格品）；一个检验参数逐步漂移（控制图判异）；一项纠正预防措施逾期。
5. **待检**：要求进货检验的物料，ERPNext 在收货单提交前要求有检验单；所以“待检”包括还没提交的收货单草稿
   （修正第 8 项只看已提交收货单的做法）。演示数据留一张待检的收货单草稿。
6. **帮助**（9b）：网页里的英文帮助页（入门、各模块、角色、常见问题），内容是 Markdown，随网页打包；
   分步引导：第一次登录时按角色走一遍主要页面，可随时重开。
7. **截图与视频**（9c）：CI 在装好演示数据的系统上用浏览器自动操作主要流程，录出截图与视频；截图随帮助页使用，
   视频作为构建产物保存，手动运行时推到 `ci/help-media` 分支（与录制 ERPNext 回复的做法相同）。
8. **测试**：模拟结果的性质（单据顺序、发货不超库存、每类典型问题都出现、同一种子结果相同）离线测；
   写入过程用模拟的 ERPNext 测；真 ERPNext 上的写入、同步后的指标与异常在 CI 安装任务里核对。

## 后果

- 演示数据随“今天”滚动，任何时候装都是“最近 90 天”
- 写入几百张单据要几分钟；CI 安装任务时间相应变长
