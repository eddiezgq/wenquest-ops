# ADR-0016：ISO 9001 过程包、体系运行状况与自动配置

- 状态：已接受（2026-10-14，项目负责人：“按建议”）
- 日期：2026-10-14
- 补充：ADR-0010（质量原则）、ADR-0011（AI 搭建质量体系，第 1、3、4、6 条）、ADR-0014（资料库）、ADR-0015（流程配置化）

## 背景

第 2 期前两项已完成：资料库（ADR-0014）让企业的程序、表单和历史台账进了系统；流程配置化（ADR-0015）让 NCR、CAPA
的流程成为有版本、经他人签字启用的配置，AI 还能按企业程序提出调整。ADR-0011 定的方向是“把标准软件化、流程化、
运行化”：一个标准是一套可运行的过程、控制点和检查规则，不是一叠文本。现在开始第一个标准：ISO 9001。

两个现实情况：

- **系统里的记录还不够覆盖 ISO 9001。** 现有的是文件控制、NCR、8D、CAPA、来料检验、供应商事实比率。ISO 9001 还要
  培训与能力、监视测量设备（校准）、内审、管理评审、质量目标、风险与机遇、顾客反馈与投诉、供应商评价等证据。
  ISO 13485 那一步（第 2 期第 4 项）会按 dee-qms 的方案完整移植这些受监管模块；ISO 9001 不需要那么重。
- **ISO 9001 正在换版。** 据认证机构公告，修订版（ISO 9001:2026）定于 2026-09-16 发布，预计有三年过渡期，期间
  ISO 9001:2015 证书继续有效。修订是演进而不是重写：沿用统一的章节结构，明确了质量文化与道德、把风险和机遇分开
  处理、更重视变更，气候变化（2024 年修正案已加入）继续保留。具体条款号以正式发布的文本为准。

## 决策

1. **过程包是数据，不是代码。** ISO 9001 过程包放在仓库里（`wqops/hub/system/packs/iso9001/`，YAML），内容：
   - **过程**：如“文件化信息控制”“不合格输出控制”“纠正措施”“内部审核”“管理评审”“能力与培训”“监视测量资源”
     “外部提供的过程、产品和服务的控制”“顾客满意”等；每个过程写明它用系统里哪个模块或登记表、哪份流程配置；
   - **控制点**：每个过程下几条“要能证明的事”，每条有：我们自己写的要求摘要（不抄标准原文）、对应条款号、
     证据从哪来、由哪条检查规则判断；
   - **检查规则**：确定性代码按记录判断，结果只有“符合 / 不符合 / 未知（缺数据）”，**缺数据一律为未知，不判符合**
     （CLAUDE.md）；每个结果都能点进看是哪些记录；
   - **适用性**：可以不适用的条款（如设计和开发）由企业声明并写理由，声明本身是签字记录。
   过程包有版本、按标准版本区分（2015 与 2026 各一份条款对照），启用、冻结、存指纹的做法与流程配置相同。
   条款对照和要求摘要由项目负责人审核后才能合并；标准原文不进系统；不承诺认证（ADR-0011 第 1、8 条）。
2. **补齐证据用“登记表”，不先做重模块。** 新增一种通用的、可配置的质量登记表：字段由过程包定义（沿用 15b 自定义
   字段的类型），可设到期日与复核周期、需要签字的步骤、附件（关联资料库文件），留痕只增不改、签字后锁定。
   ISO 9001 过程包带这几张：培训与能力、设备与校准、内审（计划、发现，发现可开 NCR / CAPA）、管理评审（输入、输出、
   决定）、质量目标（目标值、实际值、评审）、风险与机遇（两张分开，对应新版）、顾客反馈与投诉、供应商批准与复评。
   历史 Excel 可按 14c 的方式导入这些登记表（AI 提对照，人确认，代码导入）。到 ISO 13485 时，需要更严的（校准、
   投诉、培训等）按 dee-qms 换成专门模块，登记表里的数据迁过去。
3. **体系运行状况**：一页按过程列出每个控制点的结果（绿 / 红 / 灰 = 未知），附证据链接和最近一次评估时间；
   评估是只读计算，每天跑一次、也可手动刷新，每次结果存档，能看“某一天体系是什么状态”。红灯和灰灯生成待办，
   待办是普通任务（负责人、到期日），不自动改任何记录。
4. **差距报告与内审清单**：
   - 差距报告：每个控制点有没有证据、在哪；缺的列成待办；AI 可起草缺的程序或表单，进资料库草稿，走 14a 的签字审批；
   - 内审清单：按过程和控制点从记录生成，带抽样到的证据；内审员在内审登记表里记录结论，发现可直接开 NCR / CAPA。
5. **自动配置（AI 原生）**：
   - 企业先填一份简短问卷（行业、规模、场所、有无设计开发、外包过程、要认证的标准与版本），代码据此选过程包并给出
     适用性草案；
   - AI 读资料库里已生效的程序，把过程包调成企业的样子（登记表字段、复核周期、审批人、编号、哪些过程由哪份程序覆盖），
     做法与 15c 相同：每条引用原文、代码核对原文和红线、人逐条接受、进草稿、他人签字启用、冻结存指纹；
   - 企业可选不把资料送大模型，只用问卷和手工配置。
6. **程序文件由流程生成**：按当前启用的流程配置和登记表配置生成程序文件（目的、范围、职责、步骤、记录），作为资料库
   里的受控文件草稿，走 14a 的审批；配置换版后提示重新生成。生成用模板和代码，不用 AI，保证程序与系统实际做法一致。
7. **分四步交付**（每步做完汇报，等“继续”）：
   - **16a 过程包与运行状况**：过程包格式、ISO 9001 过程包（先覆盖现有模块能证明的控制点）、检查规则引擎、
     运行状况页（只读）、适用性声明。验收：每条规则有测试，缺数据判未知；条款对照经项目负责人审核。
   - **16b 登记表**：通用登记表、ISO 9001 的八张表、到期与复核规则、签字锁定、台账导入；运行状况覆盖全部控制点。
   - **16c 差距报告、待办与内审清单**；AI 起草缺的文件（人审批）。
   - **16d 问卷与 AI 自动配置、程序文件生成**。
8. **不做**：认证申请、与认证机构的对接；标准原文；ISO 14001、45001 等其他标准（之后按同一格式加过程包）；
   ISO 13485 的专门模块（第 2 期第 4 项）。

## 项目负责人的决定（2026-10-14，“按建议”）

1. **条款对照的版本**：结构按新版设计，两份对照都做。先做 ISO 9001:2015 的对照（条款号确定，现有证书都用它）；
   ISO 9001:2026 的对照在项目负责人核对正式文本后补上。
2. **证据先用通用登记表**（第 2 条），到 ISO 13485 时按需换成专门模块。
3. **审核方式**：要求摘要和条款对照由我们起草，项目负责人在 PR 里逐条审核，审过才合并；含条款对照的 PR 不自行合并。

## 16a 实施补充（2026-10-14）

- 过程包 `wqops/hub/system/packs/iso9001.yaml`：9 个过程、29 个控制点。每个控制点有我们自写的要求摘要、2015 版条款号、
  判断方式。判断方式分三种：按记录检查（12 条，`system/rules.py`）、关联资料库文件作证据（9 条，如质量方针、过程图）、
  登记表（8 条，16b 才有，目前一律“未知”）。2026 版对照待项目负责人核对正式文本后补，在此之前不能选。
- 判断哪些记录：未作废的、仍未关闭的，或在评估期（默认一年）内关闭的；很早开、最近才关的也算。从旧台账导入、
  导入时已关闭的记为历史，只计数不判断；导入后仍未关闭、在系统里继续处理的照常判断。日期一律按企业所在时区的日子。
  没有可判断的记录时结果为“未知”，不判符合。
- 有几条是用我们自己的规则来证明满足要求（标准本身可能允许别的做法），页面上注明“WenQuest Ops 规则”：让步接收由提议人
  以外的人签字批准；严重 NCR 在规定天数内（默认 14 天）有纠正措施；措施按到期日完成。天数等是过程包里的设定。
- 范围（4.3）要同时满足：关联了范围说明文件，且每个可不适用的条款都已声明适用或不适用（签字、写理由）。
- 关联作证据的文件：程序、作业指导书、表单要已生效；其他类（如作为记录保存的方针、组织图）已确认且未作废即可。
- 采用标准、声明适用性要签字；关联文件、手动检查不用签字但留记录（手动检查要能编辑质量记录）。每次评估结果存档，
  每天一次（随后台同步任务运行，默认开启；关掉同步时只能手动检查），可按日子查看当天的状态，显示时用当时的过程包版本。
- 新权限 `qms:configure`（Owner、质量）。
- 项目负责人（2026-10-14）：“规则可以是灵活设定，不要把自己搞死。关键是程序通，不要纠结细节。”因此：天数和我们自己的
  规则都是企业可改的设定（页面底部“Settings”），每条规则可以关掉，关掉后该控制点改为关联企业自己的程序作证据；
  修改留记录、立即重新检查。以后的过程包同样：先让流程跑通，细节做成可配置，不写死。

## 后果

- ISO 9001 第一次在系统里“跑起来”：每条要求有证据、有判断、有待办，审核时能直接拿出证据
- 登记表让 ISO 9001 不必等重模块，代价是到 ISO 13485 时部分数据要迁移
- 条款对照和要求摘要的质量取决于专业审核，是项目负责人把关的重点
- 新旧两版并存三年，过程包要能按版本切换
