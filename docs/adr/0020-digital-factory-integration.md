# ADR-0020：数字工厂集成（老 ERP 导入、扫码与 UDI、测量数据采集、MES 接口）

- 状态：已接受（2026-10-16，项目负责人：“好，继续”；提出时：“考虑和其它erp数据导入的问题，扫描二维码和QR code 的问题，质量数据如三坐标测量，卡尺，扫描等自动收集，集成与分析的问题……比如和MES的集成”；“我们公司太小，这些都没有，但我得考虑未来的公司模样”）
- 日期：2026-10-16
- 补充：ADR-0007（数据网）、ADR-0010（质量原则）、ADR-0014（资料库与旧台账导入）、ADR-0017（受监管模块）

## 背景

目标客户是美国和国际的中小企业，其中有一部分是制造商，包括医疗器械企业。它们上线时要把老系统的数据搬过来；
车间要能扫码；检验和生产要少手抄、多自动采集；有的企业已有 MES。项目负责人自己的公司还没有这些设备和系统，
所以本 ADR 按“未来客户的常见情况”设计，不绑定某一品牌，先做通用的入口，具体品牌的适配等有客户时再加。

## 决策

1. **老 ERP 与表格导入（20a，最先做）**。每个新客户上线都要导数据，最影响能否卖出去。
   - 支持 QuickBooks、NetSuite、SAP Business One、Odoo 等的导出文件，以及任何 Excel / CSV；
   - 做法与旧台账导入相同（ADR-0014）：AI 提议列与字段的对应并引用原表，规则可替代 AI；人逐项确认后签字导入；
   - 经 ERPNext 的 REST API 写入（不改 ERPNext），顺序为基础资料（物料、客户、供应商、计量单位、BOM）→ 期初库存 → 未完成订单；
   - 每次导入可预演（只校验不写入），失败的行列出原因，已写入的留记录；
   - 以后有客户需要时，再加 QuickBooks Online 等的直接接口。

2. **扫码与 UDI（20b）**。
   - **扫码**：手机或平板的摄像头直接在浏览器里扫码，不装 App；也支持 USB 或蓝牙扫码枪（按键盘输入处理）。
     可用于收货、领料、生产用料、追溯、召回、打开任一对象。
   - **识读**：自动识别 GS1（含 GS1-128、Data Matrix、QR）、HIBC、ICCBBA 三家发码机构的格式，拆出器械标识、
     批号、序列号、生产日期、有效期。
   - **生成标签**：用企业自己从发码机构取得的编码（GS1 的 GTIN 或 HIBCC 的 LIC 加产品号）组装 UDI，
     系统只计算校验位、不编码；输出 PDF 和斑马打印机的 ZPL。
   - 标签内容和打印记录留痕；批号、有效期取自生产记录，不让人手填两遍。

3. **测量数据自动采集（20c）**。
   - **键盘输入式量具**：数显卡尺、千分尺经 USB 或无线接收器接入，量一次数值就进入检验单或生产步骤当前的格子；
   - **文件导入**：三坐标、三维扫描等的测量报告，支持 CSV / Excel（列对应同第 1 条），以及业内通用的 Q-DAS（AQDEF）格式；
   - **车间采集程序**：放在测量电脑上，监控导出文件夹，读到新文件就送进中枢。每个文件存指纹，读数带量具编号，
     过期或停用的量具不收；
   - **用途**：数据进入来料检验、生产步骤和 SPC，判定仍由确定性代码完成；以后再加量具重复性与再现性分析（Gage R&R）。

4. **MES 接口（20d）**。
   - WenQuest Ops 不做 MES：工单在 ERPNext，现场执行在 MES，质量判定与放行在 WenQuest Ops；
   - 对外提供有文档的接口：REST 和事件推送（webhook），可选 MQTT；需要 OPC UA 时经网关接入，不在中枢里直连设备；
   - 交换的数据：工单、工序结果、用料批次（批次谱系）、不良品；从 MES 来的数据同样经过校验和留痕；
   - 没有 MES 的小厂，用我们的生产记录（17i）即可。

5. **共同原则**：采集和导入的数据都留来源和指纹；缺数据为 unknown；AI 只提议对应关系，不做判定；
   不编造任何编码、标准数值或法规条款；测试不联网，设备和文件用虚构样本。

6. **分步**：20a 导入 → 20b 扫码与 UDI → 20c 测量采集 → 20d MES 接口。每步先写细化方案再动手。

## 后果

- 新客户上线更快；车间少手抄；测量数据可追溯到量具和文件。
- 不绑定品牌，先做通用入口；具体设备和软件的适配要等真实客户提供样本文件。
- 车间采集程序是第一个装在客户电脑上的组件，安装和更新要另写说明。
